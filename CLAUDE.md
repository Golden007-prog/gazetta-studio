- `.claude/rules/design-code-review.md` — Code review skill family (dev-process, not foundational dimension). Two-phase model: Discovery (`audit-area`) + Evaluation (`review-orchestrator` + 6 angle skills: `review-diff`, `review-architecture`, `review-security`, `review-tests`, `review-types`, `review-comments`). Four consumers (local CLI, PR-comment trigger, fix-bot reviewer, autonomous `review-bot`). Companion ADRs: [0012](docs/adr/0012-skill-three-invocation-modes.md) (Skill = 3 invocation modes), [0013](docs/adr/0013-code-review-two-phase-model.md) (two-phase split).
- `.claude/rules/design-code-review-implementation.md` — 4-phase build (~3-4 weeks). P1 skill family (10 cuts) → P2 fix-bot integration (3 cuts) → P3 PR-comment workflow (3 cuts) → P4 review-bot autonomous producer with generator-critic loop (6 cuts).
- `.claude/rules/design-live-check.md` — Live check: after each publish or deploy, verify the target's live site serves what was published (published-version marker, route planner over the target's dependency indices, reports in `.gazetta/live-check/`, `afterLiveCheck` hook). Publish verification, not uptime monitoring. Research: `docs/audits/live-site-health.md`.
- `.claude/rules/design-public-storage.md` — Public storage: a target whose storage visitors can reach keeps no history, audit or review state (`publicStorage`, public by default except local filesystem targets); `isPublicSitePath` decides which stored files are served; a folder registry marks `.gazetta/` folders safe or not; the live check probes for leaks and locks publishing. Resolves #1070.
- `.claude/rules/design-target-removal.md` — Target removal: items deleted on the source are removed from a target only when the author chooses (unchecked rows in the publish list; `gazetta publish --remove`), after a check that nothing staying on the target uses them; a purge changes nothing on targets until then; `_redirects` built from per-page archive sidecars on the target. Resolves #1094.
- `.claude/rules/design-publish-undo.md` — Publish undo: undo and rollback on a publish destination restore the previous content and re-render it through the shared target-publish function (with removals), after a check against current templates. Templates stay as deployed. Resolves #1084.
- `.claude/rules/design-decision-review.md` — Decision review (dev-process; loads when working on the skill): the `review-decisions` skill approves and merges a design PR when every decision it locks traces to the maintainer's own answer in the session transcript, recorded faithfully and resting on true facts, with the AI reviewers' comments as a second opinion (Fable on request); anything only the maintainer can decide comes back as a picker question. PRs that change the skill itself stay with the maintainer.
- `.claude/rules/design-roadmap-board.md` — Roadmap board (dev-process): a public GitHub Project generated one way from ROADMAP.md by `bots/roadmap-board/`: a column per bucket, a tab per bucket and per area, draft cards for items without an issue, and a "Not in ROADMAP.md" tab. Review-decisions runs the sync after merging a ROADMAP change; GitHub's auto-add rule adds new issues.
